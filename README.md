# BloodLinkD

Blood donation and emergency request system built with Spring Boot.
REST API under `/api`, SOAP service under `/ws`, SQL database through JPA.

## Run it

Needs Java 17+ and Maven (or just STS/Eclipse/IntelliJ).

1. STS / Eclipse: *File > Import > Maven > Existing Maven Projects*, pick this folder, wait for the dependencies to download.
2. Right click `BloodLinkDApplication` > *Run As > Spring Boot App* (or `mvn spring-boot:run`).
3. App starts on http://localhost:8080 and loads demo data the first time.

Useful links
- **Web app (frontend): http://localhost:8080/**  (overview, donors, requests, donations, hospitals)
- REST example: http://localhost:8080/api/reports/summary
- H2 console: http://localhost:8080/h2-console  (JDBC URL `jdbc:h2:file:./data/bloodlink`, user `sa`, empty password)
- WSDL: http://localhost:8080/ws/bloodlink.wsdl

To start from a clean database delete the `data/` folder.
To use MySQL see the commented block in `src/main/resources/application.properties`.

## How it works

Three kinds of users: donors, hospitals, blood bank admin.

1. A **hospital** raises a blood request: patient, blood group, units, urgency, date needed.
2. `GET /api/requests/{id}/matches` returns donors who are
   - in the same city as the hospital,
   - of a compatible blood group (O- can give to everyone, AB+ can take from everyone, etc.),
   - eligible today: active, aged 18-65, last donation at least 90 days ago.
   Exact group matches come first, then people who have waited longest since their last donation.
3. Someone calls the donor. When they donate, `POST /api/donations` records it. If a `requestId`
   is given, the blood counts towards that request (it becomes FULFILLED when all units are there).
   If no request is given the unit goes into the blood bank stock.
4. A request can also be served from stock: `POST /api/requests/{id}/fulfill-from-stock`.
5. Every donation updates the donor's last donation date, so the 90 day rule applies automatically.

### Layers
```
controller  -> receives HTTP, no logic
service     -> business rules (eligibility, matching, stock)
repository  -> Spring Data JPA interfaces
model       -> JPA entities
dto         -> small request/response objects
exception   -> custom exceptions + GlobalExceptionHandler (@RestControllerAdvice)
soap        -> SOAP endpoint + JAXB classes (contract: resources/xsd/bloodlink.xsd)
static      -> frontend (resources/static: index.html, style.css, app.js)
config      -> SOAP servlet config, converters, demo data
```

### REST endpoints

| Method | URL | What |
|---|---|---|
| POST | /api/donors | register donor |
| GET | /api/donors?bloodGroup=&city= | list / filter |
| GET/PUT | /api/donors/{id} | view / update |
| DELETE | /api/donors/{id} | deactivate (history is kept) |
| GET | /api/donors/{id}/eligibility | can donate today? |
| GET | /api/donors/{id}/donations | donation history |
| POST/GET | /api/hospitals, /api/hospitals/{id} | hospitals |
| POST | /api/requests | new blood request |
| GET | /api/requests?status=OPEN | list, critical first |
| GET | /api/requests/{id}/matches | matching donors |
| POST | /api/requests/{id}/fulfill-from-stock | use stock |
| POST | /api/requests/{id}/cancel | cancel |
| POST/GET | /api/donations | record / list donations |
| GET | /api/stock, /api/stock/{group} | stock (group as `O+` or `O_POS`) |
| POST | /api/stock/{group}/add?units=5 | add units |
| GET | /api/reports/summary | dashboard numbers |

All the calls are ready to run in `docs/api-tests.http`.

### Errors (same idea as Practical 12)

| Situation | Status |
|---|---|
| validation failed, bad JSON, bad blood group, wrong id type | 400 |
| donor / hospital / request not found, unknown URL | 404 |
| wrong HTTP method | 405 |
| duplicate email / registration number | 409 |
| rule broken (donated too recently, under age, incompatible group, request closed, no stock) | 422 |
| anything unexpected | 500 |

Body is always `{timestamp, status, error, message, path}`.

### SOAP

Contract-first: `xsd/bloodlink.xsd` -> WSDL generated by Spring-WS.
Operations: `CheckStock` and `CheckEligibility`.

```
curl -H "Content-Type: text/xml" -d @docs/soap/check-stock.xml http://localhost:8080/ws
curl -H "Content-Type: text/xml" -d @docs/soap/check-eligibility.xml http://localhost:8080/ws
```
Or import `http://localhost:8080/ws/bloodlink.wsdl` in SoapUI / Postman.
Bad input (unknown donor, invalid blood group) comes back as a SOAP Fault.

## Rules you can change
`application.properties`: `bloodlink.donation-gap-days`, `bloodlink.min-donor-age`, `bloodlink.max-donor-age`.
